# 智慧党建系统 · 总体架构设计

## 一、系统架构概览

智慧党建系统基于 **Laravel 13 + Filament 5** 构建，遵循“**个人统一工作台 vs 组织管理工作台二元化、面板即身份上下文、档案与账号解耦、数据范围后端强制收敛**”的核心架构原则。系统划分为 5 个相互独立且安全隔离的 Filament 面板：

```
                    ┌─────────────────────────────────────────┐
                    │               用户访问入口               │
                    └────────────────────┬────────────────────┘
                                         │ 统一认证 / 路由分流
                                         ▼
        ┌─────────────────────────────────────────────────────────────────┐
        │                User 模型 (实现 FilamentUser 接口)                │
        │        canAccessPanel(Panel $panel) 动态身份判定与准入鉴权        │
        └──────┬─────────────────────────┬────────────────────────────────┘
               │ 个人业务 (默认工作台)    │ 管理功能 (按任职资格准入)
               ▼                         ▼
        ┌────────────┐  ┌────────────────────────────────────────────────┐
        │     /      │  │   支部管理     院级管理     组织部管理    系统管理   │
        │ 个人工作台 │  │   /branch      /college       /org       /sysadmin  │
        │ (全员可用) │  │  (支部书记)   (党委委员)   (工作人员)   (超级管理)  │
        └────────────┘  └────────────────────────────────────────────────┘
               ▲                         │
               │ 账号工号一致性关联       ▼
        ┌──────┴─────────────────────────────────────────────────────────┐
        │                      全生命周期业务覆盖                        │
        │  • 个人工作台：党员党费、学时流水、入党纪实、手机号申请、活动问答│
        │  • 管理工作台：三会一课审核、发展党员审批、组织转接、预警处置等│
        └────────────────────────────────┬───────────────────────────────┘
                                         ▼
                      ┌──────────────────────────────────────┐
                      │    DataScope / scopedOrgIds() 引擎    │
                      │ 严格按委员会在任组织或角色授权递归向下收敛 │
                      └──────────────────┬───────────────────┘
                                         ▼
                      ┌──────────────────────────────────────┐
                      │    底层数据库 (SQLite / MySQL)         │
                      │  身份证 encrypted 落库、工号字符串主键 │
                      └──────────────────────────────────────┘
```

## 二、个人工作台与管理工作台二元架构

系统确立了“**个人工作台（Personal Portal）与管理工作台（Management Portal）**”的清晰职责边界：

### 1. 个人统一工作台 (`/`)：默认全员入口
- **服务对象全覆盖**：面向全体在册用户，包括**正式党员、预备党员、入党申请人/积极分子/发展对象、非党员中层干部（学员库 Trainee）、普通教职工与协同人员**。
- **个人全业务闭环**：所有以“个人主体”发起的业务均统一收敛于此，杜绝个人业务散落或因未入党而无法使用的体验断层：
  - **党员业务**：个人党费交纳记录（`FeeRecord`）、政治生日、支部归属信息；
  - **干部与协同业务**：个人干部培训学时流水（`TrainingHour`，同时支持党员档案与党外干部学员档案 Trainee 联动）、达标进度；
  - **入党发展跟踪**：入党申请人与积极分子查看个人“一人一案”五阶段 25 步骤全流程进度（`DevelopmentCase`）、待办材料提示与超期警示；
  - **个人事务申报**：联系电话变更申请（`PhoneChangeRequest`）、组织关系转接申请（`Transfer`）、因私出国（境）及延期申请（`AbroadApplication`）；
  - **交流互动广场**：党务工作坊公开活动浏览（`WorkshopActivity`）、政策咨询问答发帖回帖（`WorkshopPost`）。

### 2. 管理工作台（`/branch`, `/college`, `/org`, `/sysadmin`）：纯粹管理职能
- 仅向具备管理职责的账号开放，专注于审核审批、台账监管、组织运行与全校调度：
  - `/branch`（党支部）：负责本支部三会一课台账填报、党员发展 25 步落地推动、手机号变更与转接初审、预警处置；
  - `/college`（二级党委）：负责本院基层组织维护、三会一课归档审核、工作坊活动登记发布与跨院报名审核、出国境与转接审批；
  - `/org`（党委组织部）：负责全校组织树与编码总控、全校党员档案、干部培训管理端直录与项目发布、出国境与转接终审、9 大类预警扫描调度；
  - `/sysadmin`（系统管理员）：负责全局账号授权、审计日志查询、数据字典与参数调控。

### 3. 顶部多身份工作台切换下拉组件
- **挂载位置**：利用 Filament 提供的 `PanelsRenderHook::USER_MENU_BEFORE` 渲染钩子，在系统顶栏用户头像（User Menu）的**正左侧**呈现；
- **自适应当前工作台**：触发按钮默认展示当前所在的 Panel 名称、专属图标与下拉箭头；
- **动态权限过滤**：下拉菜单基于 `Auth::user()->canAccessPanel($panel)` 自动甄别当前登录用户有权访问的工作台列表：
  - 当前所在工作台高亮并标注“当前”徽章；
  - 其他有权访问的工作台呈现为可一键直达的超链接；
  - 无权访问的管理工作台对该用户完全不可见，杜绝越权风险。

## 三、双轨身份与账号解耦模型

系统在设计上彻底分离“登录认证主体”与“党籍业务主体”：

### 1. 账号模型（User）与党员档案（Member）的双向解耦
- **User 主键为字符串（工号/学号）**：直接对应高校统一身份认证工号体系（如 `202600101`）。
- **Member 主键为字符串（工号/学号）**：党员档案表同样采用工号作为主键，天然与学校人力/学籍系统对齐。
- **解耦优势**：
  - 未开通系统账号的基层党员，支部和组织部可先行录入建档；
  - 党外干部（`Trainee`）和普通协同人员通过工号即可在 `/` 个人工作台享受个人学时与培训服务，无需伪造党员档案；
  - 关系采用双向关联：`User` 具有 `member_id` 唯一可空外键，`Member` 具有 `user_id` 唯一可空外键。

## 四、多面板准入判定机制

系统不依赖脆弱的前端角色切换或会话状态，而是在 [app/Models/User.php](app/Models/User.php) 的 `canAccessPanel(Panel $panel)` 中结合业务实体进行强校验：

```php
public function canAccessPanel(Panel $panel): bool
{
    return match ($panel->getId()) {
        'member' => true, // 全员默认工作台
        'branch' => $this->hasActiveCommitteeMembership(3),
        'college' => $this->hasActiveCommitteeMembership(2),
        'org' => $this->orgStaff()->where('status', '在职')->exists(),
        'sysadmin' => $this->admin()->where('status', '启用')->exists(),
        default => false,
    };
}
```

### 准入依据说明：
1. **个人统一工作台 (`/`)**：**默认工作台**，任何已登录账号均可进入，承载个人档案、党费、学时流水、入党纪实、申请与问答等业务。
2. **党支部管理面板 (`/branch`)**：必须在 `committee_members` 委员会表中存在**在任记录**（`status = '在任'` 且任期未截止），且所属组织层级 `level = 3`（党支部）。任期届满或换届离任，准入权限实时自动失效。
3. **二级党委管理面板 (`/college`)**：必须在 `committee_members` 委员会表中存在**在任记录**，且所属组织层级 `level = 2`（二级党委/党总支）。
4. **党委组织部管理面板 (`/org`)**：必须在 `org_staff` 表中存在 `status = '在职'` 的工作人员记录。
5. **系统管理面板 (`/sysadmin`)**：必须在 `admins` 表中存在 `status = '启用'` 的系统管理员记录。

## 五、数据范围（DataScope）收敛引擎

系统核心安全防线在于**数据查询范围由服务端底层 Eloquent 强收敛**，避免任何前端越权请求。

### 1. `scopedOrgIds()` 计算逻辑
在 [app/Models/User.php](app/Models/User.php) 中统一对外提供 `scopedOrgIds(): array` 方法：
- **组织部与超级管理员**：返回空数组 `[]`，在系统语义中约定**空数组代表全校范围**（不过滤组织）。
- **显式角色授权用户**：根据 `role_grants` 中的授权组织，递归获取该组织及其全部下级组织的 ID 集合。
- **委员会回退机制（关键兜底）**：普通支部书记或党委委员无需额外分配 `role_grants`，系统自动查询其在任委员所在组织（`committee_members`），并向下递归展开该组织及其全部下属组织的 ID 集合（通过组织层级树的 `path` 字段匹配 `path LIKE '0/1/2/%'`）。

### 2. Eloquent Scope 集成模式
所有涉及组织归属的模型（如 Member, Meeting, Transfer, AbroadApplication, Alert, FeeRecord 等）均统一遵循 `scopeVisibleTo` 模式：
```php
public function scopeVisibleTo(Builder $query, array $orgIds): Builder
{
    if ($orgIds === []) {
        return $query; // 全校范围
    }

    return $query->whereIn('org_id', $orgIds);
}
```
Filament 资源类在 `getEloquentQuery()` 中强制注入当前用户的权限上下文：
```php
public static function getEloquentQuery(): Builder
{
    return parent::getEloquentQuery()->visibleTo(Auth::user()->scopedOrgIds());
}
```

## 五、安全与敏感数据架构

1. **身份证全密文存储**：
   - 数据库中 `members.id_card` 字段为长文本，模型中使用 Laravel `encrypted` cast；
   - 数据库底层无法明文反查，相同明文每次写入加密密文均随机变化；
   - 系统在应用层实现 `Member::idCardExists()`，通过内存安全解密比对保障唯一性校验；
   - 列表展示默认经 `getMaskedIdCardAttribute` 脱敏（显示前 4 位和后 4 位，中间 10 位掩码），仅二级党委及组织部在明确授权场景可查看完整凭证。
2. **外部同步安全**：
   - 外部对接端点（如 `POST /fee/sync`）强制使用 Bearer/Header Token 鉴权，令牌哈希存放在系统参数表中；
   - 对接身份证比对采用标准 `SHA-256` 稳定摘要比对，避免密文不一致问题。
3. **敏感词动态过滤机制**：
   - 系统支持从数据库配置中动态加载 `workshop_sensitive_words`；
   - 提供 [app/Support/SensitiveWords.php](app/Support/SensitiveWords.php) 引擎，在问答交流、活动发表时进行不区分大小写与全半角转换的高性能字符串拦截。
